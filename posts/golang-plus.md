# Go语言底层原理

#### **一、Slice（切片）原理**
1. **本质结构**  
   - 引用类型，不存储数据，通过内部指针指向底层数组  
   - 包含三个核心字段：  
     ```go
     type slice struct {
         array unsafe.Pointer // 指向底层数组的指针
         len   int            // 当前切片长度
         cap   int            // 底层数组容量
     }
     ```
   - 与数组的区别：数组必须指定长度（如`[5]int`），切片长度动态

2. **扩容机制**  
   - 当`len >= cap`时触发扩容  
   - 扩容策略：  
     - 原容量`<1024`时，新容量直接翻倍  
     - 原容量`>=1024`时，新容量按**1.25倍**（即5/4）增长  
   - 扩容后会创建新数组，并将原数据复制到新数组

#### **二、Map（哈希表）原理**
1. **底层结构**  
   - 采用哈希表实现，核心单元是`bmap`（bucket）  
   - 每个`bmap`包含8个键值对槽位，溢出时通过指针链接下一个`bmap`

2. **查找流程**  
   ```text
   目标key → 哈希函数计算哈希值 → 取高8位定位bucket索引 → 
   取低8位与bucket中的tophash数组比较 → 匹配后比较key值 → 
   根据key索引找到对应value的索引
   ```

3. **与Java的差异**  
   - Java：哈希表冲突时使用链表/红黑树（链地址法）  
   - Go：使用固定大小的数组（每个bucket 8个槽位），溢出时链接新的bucket  
   - **优势**：减少指针开销，提高缓存命中率

#### **三、Channel（通道）原理**
1. **基本特性**  
   - 基于CSP（Communicating Sequential Processes）模型  
   - 线程安全，通过`make(chan T, capacity)`创建  
   - 无缓冲通道：发送和接收必须同时就绪（同步阻塞）  
   - 有缓冲通道：在容量范围内允许异步操作

2. **底层结构**  
   ```go
   type hchan struct {
       qcount   uint           // 缓冲区当前元素数量
       dataqsiz uint           // 缓冲区大小
       buf      unsafe.Pointer // 指向缓冲区的指针
       elemsize uint16         // 元素大小
       closed   uint32         // 关闭状态
       elemtype *_type        // 元素类型
       sendx    uint           // 发送索引
       recvx    uint           // 接收索引
       recvq    waitq          // 接收等待队列
       sendq    waitq          // 发送等待队列
       lock     mutex          // 互斥锁
   }
   ```

#### **四、GMP调度模型**
1. **核心组件**  
   - **G（Goroutine）**：  
     - 用户级协程，轻量级线程（初始栈大小2KB，最大可扩展到GB级别）  
     - 包含执行栈、PC（程序计数器）、GID（唯一标识）等信息

   - **M（Machine）**：  
     - 对应操作系统线程（OS Thread）  
     - 每个M有独立的调度栈，负责执行G

   - **P（Processor）**：  
     - 逻辑处理器，持有执行G所需的资源（如本地G队列）  
     - 数量由`GOMAXPROCS`决定（默认等于CPU核心数）

2. **调度流程**  
   ```text
   创建G → 放入P的本地队列 → M绑定P → 从队列取出G执行 → 
   G阻塞（如系统调用） → P与M解绑 → P转移到其他空闲M继续执行 → 
   G恢复后重新加入某个P的队列
   ```

3. **关键机制**  
   - **Work-Stealing**：  
     - 当M的本地队列为空时，从其他P的队列**窃取一半G**执行  
     - 保证负载均衡，减少锁竞争

   - **Hand-Off**：  
     - 当G进行系统调用导致M阻塞时，P会被转移到其他M继续执行  
     - 避免整个P资源被阻塞

   - **抢占调度**：  
     - 每个G最多占用CPU **10ms**，通过插入抢占标记（preemption flag）实现  
     - 防止某个G长时间占用CPU导致其他G饿死

4. **全局G队列**  
   - 当所有P的本地队列已满时，新创建的G会放入全局队列  
   - M执行完本地队列后，会尝试从全局队列批量获取G（通常为256个）

#### **五、GC（垃圾回收）原理**
1. **三色标记算法**  
   - **白色**：未被GC访问的对象（默认所有对象）  
   - **灰色**：已被访问但仍有子对象未处理的对象  
   - **黑色**：已被完全访问且所有子对象都被处理的对象

2. **并发标记流程**  
   ```text
   1. 初始标记（STW）：标记所有根对象（全局变量、栈变量等）为灰色
   2. 并发标记：遍历灰色对象，将其引用的白色对象标记为灰色，并将自身标记为黑色
   3. 重新标记（STW）：处理并发期间新创建或修改的引用（使用写屏障）
   4. 并发清除：回收所有白色对象占用的内存
   ```

3. **写屏障（Write Barrier）**  
   - **插入屏障**：  
     - 在灰色对象引用白色对象时，先将白色对象标记为灰色  
     - 解决“黑色对象引用白色对象”问题（强三色不变性）

   - **删除屏障**：  
     - 在删除对象引用时，将被删除的对象标记为灰色  
     - 确保被删除的对象仍能在下一轮GC中被扫描到

4. **混合写屏障（Go 1.8+）**  
   - **堆对象**：插入屏障 + 删除屏障  
   - **栈对象**：不使用写屏障，但在STW阶段重新扫描栈  
   - **新对象**：默认标记为黑色（避免在并发标记阶段被错误回收）

5. **触发条件**  
   - 内存分配量达到上次GC后堆大小的**一定比例**（默认100%）  
   - 定期触发（默认2分钟）  
   - 手动触发：调用`runtime.GC()`

#### **六、关键对比与优化建议**
1. **Slice vs Array**  
   | **特性**       | **Array**         | **Slice**         |
   |----------------|-------------------|-------------------|
   | 长度           | 固定              | 动态              |
   | 类型组成       | 包含长度（如`[5]int`） | 不包含长度         |
   | 传递方式       | 值传递（复制整个数组） | 引用传递（复制切片头） |
   | 适用场景       | 已知固定长度      | 动态长度          |

2. **Map优化建议**  
   - 预估容量：`make(map[key]value, initialCapacity)`减少扩容次数  
   - 避免频繁删除：删除会导致标记但不立即释放内存，可能触发GC  
   - 大对象存储：考虑存储指针而非值，减少内存拷贝开销

3. **并发优化建议**  
   - 控制`GOMAXPROCS`：CPU密集型建议设为`runtime.NumCPU()`，I/O密集型可适当增大  
   - 减少锁竞争：优先使用无锁数据结构（如`sync.Map`）或原子操作  
   - 合理使用缓冲通道：避免无缓冲通道导致的频繁阻塞和唤醒

4. **GC优化建议**  
   - 减少临时对象：对象复用（如`sync.Pool`）降低GC压力  
   - 控制堆大小：通过`GOGC`环境变量调整触发比例（如`GOGC=200`延迟GC）  
   - 避免大对象：超过32KB的对象会被直接分配到堆的“大对象区域”，增加GC扫描负担
